## Критерий 2. Требования и сценарий тестирования

Полный список требований и сценарии тестирования изложены в ВКР (§3.3–3.5) и в `doc/спецификация_требований.md`.

Требования к системе сформулированы с опорой на раздел 2.2 книги С. Куликова «Тестирование программного обеспечения. Базовый курс»: требования разделены на функциональные и нефункциональные, имеют идентификаторы и используются как основа для последующей проверки. Сценарии тестирования требований составлены по методу «критического пути пользователей» с выделением трёх ключевых ролей: гид, турист и администратор. ### Сценарий тестирования критического пути (3 роли)

**Роль «Гид»:** Регистрация → Создать маршрут → Добавить точки → Загрузить фото (EXIF GPS) → Дождаться WebSocket-уведомления → Проверить статистику → Включить шеринг → Открыть ссылку без авторизации.

**Роль «Турист»:** Открыть каталог → Поиск → Открыть маршрут → Клик на фото-маркер → Зарегистрироваться → Поставить оценку → Написать комментарий → Добавить в закладки.

**Роль «Администратор»:** Войти как admin → Список пользователей → Сменить роль → Удалить нарушающий маршрут → Добавить категорию → Просмотреть статистику.

## Критерий 4. Текущая версия реализации
