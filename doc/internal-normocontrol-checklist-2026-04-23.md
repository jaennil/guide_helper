# Внутренний Чек-Лист Нормоконтроля

Назначение документа: пройти финальную ручную проверку ВКР и сопутствующих материалов перед предзащитой и защитой.

Статусы:
- `[ ]` не проверено
- `[x]` проверено
- `[~]` требует уточнения или ручной доводки

## 1. Состав Итогового Пакета

- [ ] Есть итоговый PDF ВКР: `doc/latex/main.pdf`
- [ ] Есть исходники LaTeX в `doc/latex/`
- [ ] Есть ссылка на GitHub-репозиторий
- [ ] Есть PDF-презентация: `doc/presentation/guide-helper-defense.pdf`
- [ ] Есть demo-пакет: `doc/demo/`
- [ ] Есть fallback-видео: `doc/demo/guide-helper-defense-demo.mp4`

## 2. Обязательные Разделы ВКР

- [ ] Титульный лист присутствует
- [ ] Задание на ВКР присутствует
- [ ] Аннотация присутствует
- [ ] Содержание присутствует
- [ ] Введение присутствует
- [ ] Глава 1 присутствует
- [ ] Глава 2 присутствует
- [ ] Глава 3 присутствует
- [ ] Заключение присутствует
- [ ] Список источников присутствует
- [ ] Приложения присутствуют

## 3. Тема, Цель, Задачи

- [ ] Формулировка темы одинакова в титуле, задании, введении, презентации и отчётах
- [ ] Цель соответствует теме
- [ ] Задачи сформулированы через глаголы
- [ ] Каждая задача покрыта хотя бы одним разделом работы
- [ ] Нет параграфов, не относящихся ни к одной задаче

## 4. Объём И Источники

- [ ] Основной текст без служебных страниц не меньше 60 страниц
- [ ] Число источников не меньше 50
- [ ] В тексте есть ссылки на источники
- [ ] Нет явных утверждений без ссылок там, где они нужны
- [ ] Числа в аннотации совпадают с фактическим PDF

## 5. Оформление Текста

- [ ] Используется `Times New Roman`
- [ ] Межстрочный интервал соответствует требованиям методички
- [ ] Абзацный отступ одинаковый по всему документу
- [ ] Заголовки оформлены единообразно
- [ ] Нет визуально сломанных переносов в заголовках
- [ ] Нет пустых полустраниц из-за неверных разрывов
- [ ] Колонтитулы и нумерация страниц не выглядят сломанными

## 6. Таблицы И Рисунки

- [ ] Все рисунки имеют подписи
- [ ] Все таблицы имеют подписи
- [ ] Подписи оформлены единообразно
- [ ] На все рисунки есть ссылки в тексте
- [ ] На все таблицы есть ссылки в тексте
- [ ] Нумерация рисунков корректна
- [ ] Нумерация таблиц корректна
- [ ] В приложениях нумерация таблиц и рисунков содержит букву приложения
- [ ] Нет таблиц и рисунков, вылезающих за границы страницы

## 7. Приложения

- [ ] Приложения перечислены в содержании
- [ ] Названия приложений согласованы с тем, что реально внутри
- [ ] В тексте есть ссылки на приложения
- [ ] Таблицы и рисунки в приложениях оформлены отдельно от основного текста

## 8. Аннотация

- [ ] Аннотация укладывается в разумный объём
- [ ] В аннотации указаны актуальные числа страниц, рисунков, таблиц и источников
- [ ] Формулировки в аннотации соответствуют реальному scope работы
- [ ] В аннотации нет противоречий с текстом ВКР

## 9. Содержательная Согласованность

- [ ] ВКР, презентация и demo используют один и тот же baseline результата
- [ ] Android-клиент везде позиционируется одинаково как companion app
- [ ] AI-контур везде описан как дополнительный интеллектуальный слой, а не как ядро системы
- [ ] В тексте нет противоречий по статусу требований
- [ ] В тексте нет противоречий по архитектуре и составу сервисов

## 10. Презентация

- [ ] Есть титульный слайд
- [ ] Есть слайд с актуальностью
- [ ] Есть слайд с целью и задачами
- [ ] Есть слайды по архитектуре и реализации
- [ ] Есть слайд по тестированию
- [ ] Есть итоговый слайд
- [ ] На промежуточных слайдах есть единый нижний колонтитул
- [ ] Формулировки на слайдах не противоречат ВКР
- [ ] Числа на слайдах не противоречат ВКР

## 11. Демо

- [ ] Есть канонический live demo flow
- [ ] Есть fallback-цепочка `live -> video -> screenshots`
- [ ] Для demo подготовлены тестовые данные
- [ ] Есть одна публичная ссылка на маршрут
- [ ] Есть один маршрут в профиле автора
- [ ] Есть короткий Android-сценарий как дополнительный контур

## 12. Устная Защита

- [ ] Есть короткий ответ “что за система разработана”
- [ ] Есть короткий ответ “какую проблему решает работа”
- [ ] Есть короткий ответ “в чём практическая ценность”
- [ ] Есть короткий ответ “почему микросервисы”
- [ ] Есть короткий ответ “зачем AI”
- [ ] Есть короткий ответ “почему web основной, mobile дополнительный”
- [ ] Есть короткий ответ “почему это не просто CRUD”

## 13. Что Проверить В Последний День

- [ ] PDF ВКР открывается и визуально выглядит нормально
- [ ] PDF презентации открывается и визуально выглядит нормально
- [ ] Репозиторий не зависит от случайных локальных незакоммиченных правок
- [ ] Demo-файлы лежат в ожидаемых путях
- [ ] GitHub-репозиторий доступен
- [ ] Есть локальная копия всех ключевых PDF и demo-файлов

## 14. Критерий Готовности

ВКР можно считать готовой к внутреннему нормоконтролю, если одновременно выполнено следующее:
- структура полного комплекта собрана;
- объём и источники проходят по порогам;
- оформление не содержит явных ошибок;
- презентация и demo синхронизированы с текстом;
- есть понятный устный narrative без расширения scope.
