# План Презентации К Защите ВКР

Тема ВКР: `Разработка информационной системы для создания и публикации туристических маршрутов с геопривязанными фотографиями`

Цель документа: быстро собрать презентацию под требования преддипломной практики и будущей защиты без повторного придумывания структуры с нуля.

## Общие Правила

- Формат: `16:9`
- Базовый шрифт: `Times New Roman` или близкий академический шрифт без декоративности
- На всех слайдах, кроме первого и последнего, нижний колонтитул:
  `Дубровских Н. Е. | 221-361 | Разработка информационной системы для создания и публикации туристических маршрутов с геопривязанными фотографиями | май 2026`
- На одном слайде не более `5–7` коротких тезисов
- Основной принцип: не пересказывать текст ВКР, а показывать проблему, решение, архитектуру, результаты и практическую ценность

## Рекомендуемая Структура

### Слайд 1. Титульный

Содержимое:
- тема ВКР;
- ФИО;
- группа;
- руководитель ВКР;
- кафедра;
- год.

Визуал:
- нейтральный фон;
- без перегруза;
- можно добавить небольшой фрагмент карты или приглушённый screenshot системы.

### Слайд 2. Актуальность И Проблема

Тезисы:
- маршруты, фотографии и пояснения обычно разрознены по разным инструментам;
- гид вынужден собирать итоговый маршрут вручную;
- существующие сервисы не дают единого контура создания, публикации и визуального сопровождения маршрута;
- для активного туризма важны фото, комментарии, точки интереса и доступность в пути.

Визуал:
- схема проблемы `карта + мессенджер + фото + GPX` как разрозненный набор;
- или один сильный скрин редактора маршрута как контраст к проблеме.

### Слайд 3. Цель И Задачи

Тезисы:
- цель: разработать информационную систему Guide Helper для создания и публикации туристических маршрутов с геопривязанными фотографиями;
- краткий список 10 задач, лучше сгруппированный в 4 блока:
  - анализ;
  - проектирование;
  - реализация;
  - проверка эффективности.

Визуал:
- компактная блок-схема из 4 этапов.

### Слайд 4. Анализ Предметной Области И Аналоги

Закрываем задачи:
- анализ предметной области;
- сравнительный анализ аналогов.

Тезисы:
- целевые роли: гид, турист, администратор;
- рассмотрены Wikiloc, Google My Maps, Strava, Komoot, AllTrails;
- у аналогов нет нужного сочетания геопривязанных фото, интерактивного шеринга и единого рабочего контура.

Визуал:
- фрагмент сравнительной таблицы;
- короткая диаграмма с итоговым рейтингом аналогов.

### Слайд 5. Требования К Системе

Закрываем задачу:
- формирование требований.

Тезисы:
- `37` функциональных и `6` нефункциональных требований;
- требования сгруппированы по блокам: аутентификация, маршруты, фото, социальные функции, каталог, администрирование, AI, аналитика;
- требования используются как основа тестирования и приёмки.

Визуал:
- укрупнённая матрица требований;
- можно вынести `FR-06`, `FR-13`, `FR-31` как самые показательные.

### Слайд 6. Архитектура Системы

Закрываем задачу:
- проектирование архитектуры и базы данных.

Тезисы:
- микросервисная архитектура;
- отдельные сервисы аутентификации, маршрутов, обработки фотографий, кеширования и тайлов;
- внешние провайдеры: карты, геокодинг, маршрутизация, погода, LLM API;
- развёртывание в Kubernetes.

Визуал:
- C4 container diagram из ВКР.

### Слайд 7. Модель Данных И Алгоритмы

Закрываем задачу:
- проектирование БД и алгоритмической базы.

Тезисы:
- маршруты, точки, фото, комментарии, лайки, рейтинги, закладки, диалоги;
- JSONB для точек маршрута;
- Хаверсин для расстояния;
- правило Найсмита для оценки времени;
- расчёт профиля высот и сложности.

Визуал:
- ER-диаграмма;
- маленький блок с формулами/алгоритмами.

### Слайд 8. Реализация Backend

Закрываем задачу:
- реализация серверной части.

Тезисы:
- Rust + Axum;
- JWT access/refresh;
- CRUD маршрутов и социальные функции;
- репозиторный слой на sqlx;
- API для каталога, профиля, публикации и статистики.

Визуал:
- схема основных backend-эндпоинтов;
- можно показать короткий фрагмент API-таблицы.

### Слайд 9. Обработка Фотографий И AI-Функции

Закрываем задачи:
- обработка геопривязанных фотографий;
- интеллектуальные функции.

Тезисы:
- асинхронный конвейер фото через NATS JetStream и MinIO;
- генерация миниатюр и привязка фото к точкам;
- AI-ассистент с tool use;
- генерация описания маршрута по фотографиям.

Визуал:
- sequence diagram обработки фото;
- короткая схема tool-calling.

### Слайд 10. Клиентское Приложение

Закрываем задачу:
- разработка клиентских интерфейсов.

Тезисы:
- React PWA;
- desktop-оболочка на Tauri;
- интерактивная карта;
- профиль, каталог, публичный просмотр маршрута, админ-панель.

Визуал:
- 3–4 актуальных скриншота: редактор маршрута, публичный маршрут, каталог, профиль.

Примечание:
- если решишь включать мобильный клиент в защитный baseline, тогда здесь нужен отдельный подпункт `мобильный прототип записи маршрута`;
- если не решишь, мобильный клиент на слайдах лучше не делать центральным элементом.
